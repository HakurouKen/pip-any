# Pip Any 设计

状态：需求已确认，已完成实现及自动化验证。

## 已确认

- 构建 TypeScript Chrome 扩展，可选择网页元素并放入浏览器画中画浮窗。
- 点击 Chrome 工具栏上的插件图标打开 popup，通过「选择内容」进入选择模式；再次打开 popup 时显示「取消选择」。
- 单纯打开 popup 只读取选择状态；受限页面在 popup 中显示原因。
- 鼠标悬停时高亮目标元素，单击后锁定选区，提示区显示范围滑块及「确定」「重新选择」按钮。
- 锁定后移动鼠标不改变选区；点击「重新选择」回到悬停预览。
- 按 Esc 取消选择。
- 滑块向右扩大到父元素，向左缩小至初始元素；↑ / → 扩大，↓ / ← 缩小，四个方向键与滑块同步。
- 到达最小或最大范围后停止调整；滑块只有一个层级时禁用，但仍可打开浮窗。
- 点击「确定」后才创建或替换浮窗，取消锁定不会搬移元素。
- 显示当前选择范围。
- 普通选区使用 Document Picture-in-Picture 移动原元素，原位置保留等尺寸占位，浮窗关闭时恢复。
- iframe 自身及包含 iframe 的区域禁选；悬停时显示红色斜纹虚线框、“不可选”文案与禁止光标，点击不锁定。
- 已锁定普通元素后，滑块或方向键可预览含 iframe 的父范围，但无法确认打开；缩小到有效范围后恢复正常。
- 尽力保留样式与交互，不保证任意网站的样式和事件完全保留。
- 首版支持普通 HTTPS 页面的顶层元素，不支持 iframe 内部选择及浏览器内部页面。
- 扩展仅使用 activeTab 和 scripting 权限，由用户点击插件后访问当前页面。
- 已有浮窗时，从插件 popup 点击「选择内容」重新进入选择模式；锁定新选区并确认打开成功后替换浮窗内容。
- 取消重新选择时保留现有浮窗。
- 初始窗口尺寸跟随元素并受可用屏幕限制，内容超出时可滚动。
- 浮窗外层填满可用区域，选中元素默认宽度 100%、高度 auto，移除原始最小宽高限制；保留元素内部间距，使用 border-box 将边框和 padding 计入宽度。仅外层负责页面滚动，不强制拉伸内容高度；关闭时恢复原内联样式。
- 不支持的页面及打开失败时显示中文原因，允许取消或重试；替换失败时尽量保留旧内容。
- 优先恢复原位置；原容器已不存在时放回页面底部并提示。
- 源页面刷新或关闭后浮窗结束；不自动重新绑定网站重建的元素。

## 实现说明

### 界面约定

- 工具栏 popup 与页面内选择提示区统一使用浅蓝背景、深色文字和蓝色主操作；普通选区高亮也使用蓝色，禁选和错误继续使用红色。
- popup 展示 Pip Any 和用途说明“将任意页面元素转为画中画”，主按钮显示“选择内容”；未进入选择模式时不显示默认状态说明，选择状态及错误原因仍保留，不展示底部操作说明。
- 页面提示区初始说明为“点击选择对应内容。”，正常确认按钮显示“确定”；锁定后保留范围调整说明，忙碌和禁选状态继续显示对应提示。保留当前目标、尺寸、方向键、取消和重选入口。
- 精简说明不删除错误原因和恢复建议，不改变选择流程、支持范围或画中画浮窗内的网页样式。

### 选择与浮窗

- content script 在隔离世界中运行；重复注入只切换同一个选择器。
- popup 在临时页面访问权限下读取选择状态，点击操作按钮后注入内容脚本并关闭面板；无需后台 service worker。
- 选区锁定后保留初始元素到可选祖先的层级链，滑块和方向键使用同一层级索引。
- 滑块获得焦点时统一处理四个方向键，防止原生 range 行为导致一次按键重复调整。
- 透明选择层接收 iframe 上方的指针事件，临时穿透命中原元素；页面提示区仍可交互，退出选择后撤去拦截。
- 在 iframe 本身、普通后代和开放 Shadow DOM 中检测到 frame 时阻止选定；封闭组件内部无法检查。
- 确认前重新检查禁选条件；浮窗请求等待期间若选区新增 iframe，取消搬移并提示重选。尝试替换成禁选区域时保留现有浮窗。
- 保留透明选择层以阻止 iframe 内部收到选择点击；不改变原 iframe 的样式、位置或文档归属。退出选择时隐藏选择层和特殊标记。
- Shadow DOM 可选择宿主，暂不进入其内部选择。
- Esc 也会取消正在等待窗口创建的操作，防止退出选择后仍搬走元素。

## 插件 UI 模板维护方案

状态：已实施，自动化检查及部分浏览器抽查已完成；正式工具栏注入链路尚未验证，见 [验证记录](testing.md#证据与结果)。以下方案保持现有行为和视觉效果。

### 目标与范围

- 优先分离静态结构、样式与交互逻辑，改善阅读和编辑体验；不以减少代码行数或合并相似片段为目标。
- 仅将插件自己的 overlay 和 popup 纳入 UI 模板维护范围，不迁移 UI 框架，不引入模板引擎。
- 网页内容仍搬移原节点；网页样式复制、占位与浮窗布局覆盖不纳入 UI 模板，保留其节点身份和恢复逻辑。

### 结构与样式

- overlay 使用独立的静态 HTML 片段和 CSS 文件；通过构建时文本导入嵌入 content 脚本，初始化时同步创建结构并放入原有 ShadowRoot。
- HTML 片段没有动态插值、条件、循环或自定义占位符；不包含脚本、内联事件处理器和运行时外部资源依赖。动态文案仍使用 `textContent`，状态通过 DOM 属性更新，事件在 TypeScript 中绑定。
- popup 保留 `public/popup.html` 作为静态页面，将内嵌样式移入独立 CSS 文件，沿用 public 资源复制方式，不引入第二套渲染流程。
- 暂不共享主题文件、布局或按钮组件。少量重复的颜色变量不足以抵消跨普通文档和 Shadow DOM 的共享复杂度。
- 保留 overlay 宿主的少量防网页干扰内联声明及其优先级；动态几何属性继续通过具体 CSS 属性更新。
- 保持原有节点顺序、ARIA、焦点、事件路径与命中测试行为；不引入运行时资源请求或异步模板准备，不改变申请浮窗的用户激活时序。

### 模板与逻辑的契约

- 保持 `createOverlay(document, actions)` 对外接口，显式使用传入的文档创建节点，不隐式依赖全局 `document`。
- 使用专用 `data-ui` 属性标记需要操作的节点，避免将样式 class 同时作为逻辑绑定契约。
- 在局部初始化函数中校验必要节点存在、唯一且类型正确；控件校验以传入文档对应的 DOM 环境为准。全部校验通过后再挂载，错误应明确指出缺失或不符合要求的控件。
- 初始化后保留各实例自己的节点引用，不在每次状态更新时重新查询，不创建通用模板框架。

### 验收与证据边界

- 运行现有测试，并补充模板控件契约、动态文本不被解析为 HTML、多实例节点引用隔离的测试。
- 检查格式、类型与构建结果，确认 content 产物仍自包含，没有运行时模板资源请求或 ESM 导入。
- 真实扩展入口抽查 popup 和 overlay 的视觉效果、选择层命中、滑块焦点及按钮操作；参考 [自测指南](testing.md) 执行并记录。
- 若无法完成真实扩展验证，明确报告未覆盖部分；模拟 DOM 测试和构建检查不替代真实入口证据。

## 已核实的技术约束

- Document Picture-in-Picture 可容纳任意 HTML，Chrome 桌面端从 116 起支持。
- 打开窗口要求用户手势，应在点击「确定」按钮时尽早请求窗口。
- 官方示例移动原 DOM 节点，并在浮窗关闭时恢复；样式需要显式复制。
- 原页面关闭或导航到新文档会关闭浮窗。
- 任意网站的样式与交互不能仅凭移动节点保证完全保留。

参考：[Document Picture-in-Picture](https://developer.chrome.com/docs/web-platform/document-picture-in-picture)。
